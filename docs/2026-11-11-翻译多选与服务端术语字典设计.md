# 翻译多选与服务端术语字典设计

- 日期：2026-11-11
- 状态：已实施（服务端 `8f01e36`，插件 `6a8855a`；三目标构建与单元测试已过，待实机验收）
- 涉及仓库：`jellyfin-plugin-metatube`（插件）、`metatube-sdk-go`（服务端）

## 1. 背景与目标

旧的翻译链路有三个彼此独立的功能：

1. `TranslationMode` 单选：关闭 / 标题 / 简介 / 标题+简介；
2. `EnableSeriesTranslation` + 本地「系列译文对照表」：只翻系列名，译文存在插件 XML 配置里；
3. 标题、演员、类别三套「替换表」：按子串做查找替换，与翻译无关。

用户要求：

- 翻译模式改成**多选**：勾选哪一项，页面就显示哪一项的译文，合集、标签等派生数据也用译文生成；
- 把「翻译系列名」「启用标题替换」「启用演员替换」「启用类别替换」全部并入翻译功能；
- 现有替换功能没有价值，整体移除；
- 演员名、系列名、类别等**术语**翻译一次后存到服务端数据库，下次先查库，命中就直接用；
- 标题、简介**不入库**，每次直接翻译；
- 不迁移旧数据，元数据后续重新刮削，因此只考虑新逻辑；合集也由用户后续重新生成，不做新旧名归一。

目标语言硬编码为 `zh-CN`。旧实现里「原文已含汉字就跳过翻译」的判定整体删除：勾选即翻译，不再区分汉字/假名。

## 2. 总体流程

```
GetMetadata
  ├─ 保留 OriginalTitle
  ├─ EnableRealActorNames（保留，翻译之前执行）
  ├─ 翻译（TranslationHelper）
  │    ├─ 标题 / 简介 ──→ GET /v1/translate（每次直译，不查库）
  │    └─ 系列 / 类别 / 演员（术语）
  │         本地进程缓存
  │           → 未命中：GET /v1/translations/term（服务端 SQLite）
  │           → 未命中：GET /v1/translate
  │           → 写回：PUT /v1/translations/term（首写优先）
  │           → 使用服务端返回的生效译文
  ├─ 去重（类别/演员/剧照）
  ├─ 模板参数（{title}/{series}/{maker}/{label}/{actors}/{first_actor}…）
  ├─ 合集 / Studio / 标签（全部取翻译后的值）
  └─ 演员：显示译名，但 pid 与头像仍用「原始名」搜索
```

## 3. 服务端设计（metatube-sdk-go）

### 3.1 数据表

新增 `model.TranslationInfo`，表名 `translation_metadata`：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | 自增主键 | |
| `kind` | varchar(16)，非空 | `actor` / `series` / `genre`（`maker` / `label` 仍被服务端接受，用于兼容旧插件，新插件不再写入） |
| `target_lang` | varchar(16)，非空 | 目标语言，归一化为小写，目前恒为 `zh-cn` |
| `source_key` | varchar(512)，非空 | `TrimSpace` + 小写化后的源文本，用于匹配 |
| `source_text` | varchar(512)，非空 | 原始源文本（保留大小写，便于排查） |
| `translated_text` | varchar(512)，非空 | 译文 |
| `engine` | varchar(32) | 首次生成该译文的引擎，仅诊断用 |
| `created_at` / `updated_at` | 时间 | 复用 `TimeTracker` |

唯一索引 `idx_translation_metadata_term (kind, target_lang, source_key)`。

归一化规则在服务端集中实现，插件只负责传原文：

- `kind`、`target_lang`、`source_key` 一律 `TrimSpace` + `ToLower`；
- 译文 `TrimSpace`；源文本与译文都不得为空；
- 术语译文含 `\r` 或 `\n` 时拒绝写入（术语要直接当合集名/标签/演员名用）。

### 3.2 接口

放在现有**私有**路由组（有 token 时校验 Bearer，未配置 token 时开放），不参与 `cachePublicSMaxAge`：

**查询**：`GET /v1/translations/term?kind=actor&target_lang=zh-CN&source=Yui%20Hatsumi`

```json
{"data":{"found":true,"translated_text":"柚井初美"}}
```

未命中返回 200：

```json
{"data":{"found":false}}
```

**写入**：`PUT /v1/translations/term`

```json
{"kind":"actor","target_lang":"zh-CN","source":"Yui Hatsumi","translated_text":"柚井初美","engine":"Baidu"}
```

- 语义是**首写优先**：唯一键已存在时保留已有译文，不覆盖；响应返回实际生效的译文。
- 返回：`{"data":{"found":true,"translated_text":"<生效译文>"}}`。
- `kind` 不在白名单、任一必填字段为空、文本超过 512 字符、译文含换行 → 400。

实现方式：`INSERT ... ON CONFLICT DO NOTHING` 后按唯一键回查。SQLite 与 Postgres 都由 GORM 的 `clause.OnConflict{DoNothing: true}` 支持，天然处理并发。

### 3.3 迁移

- `engine/database.go` 的 `DBAutoMigrate` 列表加入 `&model.TranslationInfo{}`；
- `engine/dbengine/dbengine.go` 的同名列表也加入（该抽象尚未接入生产，但保持两处一致，避免以后切换时漏表）；
- SQLite 由 `cmd.Router` 强制开启自动迁移；Postgres 需要启动参数 `-db-auto-migrate`，沿用现有约定。

### 3.4 部署

本文字典必须落在**文件 SQLite**上才能跨重启保留：

```bash
-dsn /data/metatube.db
```

仓库 README 已说明默认 `file::memory:?cache=shared` 重启即丢；容器需把 `/data` 挂成持久卷。未配置文件 DSN 时功能仍可用，但每次重启后字典为空，会重新调用翻译引擎。

## 4. 插件设计

### 4.1 配置项

删除：

- `TranslationMode`（含 `Translation/TranslationMode.cs`）；
- `EnableSeriesTranslation`、`RawSeriesTranslationTable`；
- `EnableTitleSubstitution`、`TitleRawSubstitutionTable`、`GetTitleSubstitutionTable()`；
- `EnableActorSubstitution`、`ActorRawSubstitutionTable`、`GetActorSubstitutionTable()`；
- `EnableGenreSubstitution`、`GenreRawSubstitutionTable`、`GetGenreSubstitutionTable()`。

新增 7 个布尔项，默认全部 `false`（翻译功能默认关闭，目标语言固定 `zh-CN`）：

| 属性 | 页面文案 | 作用 |
| --- | --- | --- |
| `TranslateTitle` | 翻译标题 | `m.Title` |
| `TranslateSummary` | 翻译简介 | `m.Summary` |
| `TranslateSeries` | 翻译系列名 | `m.Series` → 合集名 / 系列标签 / `{series}` |
| `TranslateGenre` | 翻译类别 | `m.Genres` 逐个 |
| `TranslateActor` | 翻译演员名 | `m.Actors` 逐个，显示译名 |

片商与厂牌不参与翻译（2026-11-11 用户要求移除）：`m.Maker` / `m.Label` 原样进入 Studio、标签与模板变量。

引擎选择与各引擎凭据保留不变。Emby 侧沿用属性驱动的 `[DisplayName]` 复选框；Jellyfin 侧改 `configPage.html`。

### 4.2 翻译顺序与演员映射

1. `OriginalTitle` 取翻译前的 `m.Title`（现有行为不变）；
2. `EnableRealActorNames` 先执行，再做翻译；
3. 标题、简介用现有引擎链路直译，失败保留原文（现有 `TranslateFieldSafeAsync` 语义）；
4. 术语逐项走 `TermTranslationService`；
5. 演员翻译时记录 `译名 → 原名` 映射（`OrdinalIgnoreCase`，重复译名保留第一个原名）；
6. `m.Actors` 改为译名数组，后续去重、模板、`PersonInfo.Name` 全部用译名；
7. `SetActorImageUrl` 增加 `searchName` 参数：pid 与头像仍然用**原名**调用 `/v1/actors/search`，避免用中文名搜不到演员或匹配错人。

不允许把「原名」写进 `PersonInfo.ProviderIds` 之外的显示字段；演员条目的 `Name` 必须是译名，演员合集的分组、匹配、封面都按译名与 pid 走。

### 4.3 术语服务

新增 `Translation/TermTranslationService`：

- `TermKind`：`Actor` / `Series` / `Genre`；
- 进程级缓存：key = `kind + ":" + source.Trim().ToLowerInvariant()`，值与服务端一致；
- 解析顺序：缓存 → 服务端 GET → 引擎翻译 → 服务端 PUT → 返回生效译文；
- 服务端返回的生效译文优先于本地译文（并发下另一部影片可能已先写入）；
- 译文为空或含换行：返回原文，不写库、不缓存；
- 引擎失败：返回原文，不写库、不缓存（下次还能重试）；
- 译文与原文相同：视为引擎调用成功，正常写库并缓存，避免下次重复调用；
- 同一术语在进程内只查一次库、只翻一次。

服务端不可用（旧版本 404、网络错误、DB 错误）：进程内标记字典不可用，后续术语跳过 GET/PUT，直接调引擎；只记一条 Warn。翻译功能本身不受影响，只是不落库。

## 5. 失败与降级

| 场景 | 行为 |
| --- | --- |
| 服务端是旧版本，没有术语接口 | 首次 404 → 记一条 Warn，进程内禁用字典；术语直译，不落库 |
| 服务端网络错误 / 数据库错误 | 同上；翻译本身继续走 `/v1/translate` |
| 翻译引擎失败 | 该字段保留原文；术语不写库、不缓存，下次重试 |
| 服务端写入失败 | 使用本地译文，本次刮削不受影响 |
| 译文含换行 | 保留原文，不写库（术语要当名字用） |
| 服务端未配置文件 SQLite | 功能可用，重启后字典丢失；部署文档强调 `-dsn` |

## 6. 明确不做

- 不迁移旧的 `TranslationMode`、系列译文表、三套替换表；不做兼容读取。
- 不做新旧演员名/系列名的归一或合并；旧合集与旧演员条目由用户重新刮削、重新生成合集后自然替换。
- 标题、简介不进数据库。
- 不为术语字典做插件侧管理界面；误译可直接改服务端 SQLite 行或删除该行后重刮。
- 不按 provider 区分演员同名（字典键只有 kind + 目标语言 + 源文本）。
- 不改演员合集的分组/匹配算法；本轮只改变进入算法的名字来源。

## 7. 测试与验收

### 7.1 服务端（Go，SQLite 内存库，不依赖 Docker）

- 保存后可查询；重复保存首写优先；大小写/首尾空白归一；`kind`、`target_lang` 隔离；未命中返回 `ErrRecordNotFound`；空值与超长拒绝。

### 7.2 插件（xUnit）

- `TermTranslationService`：服务端命中不调引擎；未命中调引擎并回写；回写返回的生效值优先；进程缓存命中不重复请求；引擎失败返回原文且不缓存；换行译文拒绝；空白输入原样返回。
- 演员映射：译名用于显示、原名用于搜索（纯函数级验证）。
- 保留并继续跑现有演员合集、封面改写、空合集清理等测试。
