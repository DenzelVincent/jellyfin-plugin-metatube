# MetaTube 插件技术说明

> 适用仓库：`DenzelVincent/jellyfin-plugin-metatube`（上游 `metatube-community/jellyfin-plugin-metatube` 的个人维护分支）
> 文档基线：main 分支 `8fb0d26`（2026-11-15）。配套服务端文档见 metatube-sdk-go 仓库 `docs/2026-11-15-SDK技术说明.md`。

## 1. 项目概述

本插件是 Jellyfin / Emby 的成人影片元数据刮削插件，本身不抓取站点，所有元数据、搜索、图片与翻译能力都通过 HTTP 调用 MetaTube 服务端（metatube-sdk-go）获得。插件侧的职责是：

- 把媒体文件名收敛成番号，向服务端搜索/取详情，填充影片与演员元数据；
- 解析演员身份（别名表 + 候选名池回写），显示服务端优选的艺名；
- 按配置翻译标题/简介/系列/类别（主辅引擎 + 服务端术语字典）；
- 维护演员合集、多人共演合集、无演员影片合集（仅 Jellyfin）；
- 把主图下载到媒体目录本地化，并守护指针不被远程刷新冲掉；
- 按文件名检出中文字幕/无码破解，向服务端图片接口请求角标合成。

同一份代码通过 `__EMBY__` 编译符号双平台构建：Jellyfin 版功能完整（合集、主图守护、配置页），Emby 版保留刮削/翻译/角标/预告片/自动更新，不含合集体系。

### 1.2 构建与版本

- 目标框架成对切换（`Jellyfin.Plugin.MetaTube.csproj`）：
  - Jellyfin：`JellyfinSdkVersion` 默认 `10.11.0` + `net9.0`（当前发布基线）；12.x 适配走 `preview-jellyfin-build.yml` 传参试编（12.x 包只支持 `net10.0`，只换版本不换框架会 NU1202）。
  - Emby：`net6.0` + `MediaBrowser.Server.Core 4.9.1.80`，定义 `__EMBY__`（Emby 4.8/4.9 运行时是 .NET 6，net8+ 程序集会静默加载失败）。
- 版本号：`yyyy.Mdd.Hmm.0`，时间戳固定北京时间（`DateTime.UtcNow.AddHours(8)`，CI runner 是 UTC）。
- Release 构建后自动打包 `Jellyfin.MetaTube@v{版本}.zip` / `Emby.MetaTube@v{版本}.zip`（只含 MetaTube.dll）。
- 发布：`publish-plugin.yml` 仅在 `v*` tag 推送（或手动）时跑，产物为 GitHub Release（两个 zip）+ `dist` 分支的 `manifest.json`（`scripts/manifest.py` 生成，GUID 与 `Plugin.Id` 一致）。
- 测试：`dotnet test`，xUnit，`RollForward=LatestMajor`（兼容 WSL 只有 .NET 10 运行时的环境）。当前 10 个测试文件、109 个执行用例（102 个 `[Fact]` + 2 个 `[Theory]` 共 7 组 `[InlineData]`；按属性数是 104）。

## 2. 插件入口与生命周期

### 2.1 Plugin（Plugin.cs）

- Jellyfin：`BasePlugin<PluginConfiguration>, IHasWebPages`；Emby：`BasePluginSimpleUI<PluginConfiguration>, IHasThumbImage`。
- 常量：`ProviderName = ProviderId = "MetaTube"`；插件 GUID `01cc53ec-c415-4108-bbd4-a684a9801a32`（manifest 必须同值）。
- 静态 `Instance` 供全局取配置；`GetPages()` 注册嵌入式配置页 `Configuration.configPage.html`（仅 Jellyfin）。

### 2.2 后台服务注册（仅 Jellyfin）

| 服务 | 注册器 | 作用 |
|---|---|---|
| `CollectionWatcher`（IHostedService） | `CollectionWatcherServiceRegistrator` | 监听库事件，即时维护合集（见 §8.4） |
| `PrimaryImageGuardEntryPoint`（IHostedService） | `ServiceRegistrator`（PrimaryImageGuard.cs） | 主图本地化守护（见 §9.4） |

### 2.3 配置页（configPage.html）

Jellyfin 专用单页，分区：General / Badge / Image / Provider / Template / Translation。要点：

- 服务器地址校验 `^https?://.+$`；翻译区 4 个勾选 + 主引擎（OpenAI Key/URL/Model）+ 辅引擎下拉（None/Baidu/GoogleFree），选 Baidu 才显示凭据输入（`updateTranslationSettingsVisibility`）。
- 演员合集媒体库白名单：`pageshow` 时调 `Library/VirtualFolders` 动态渲染 `emby-checkbox` 列表（`document.createElement('input', 'emby-checkbox')` 字符串形式传 typeExtension），提交时收集勾选的库 Guid 存 `ActorCollectionLibraryIds`。
- 页面自带中文本地化脚本（`localize()` 遍历文本节点替换）。
- Emby 无 HTML 页，配置项用 `EditableOptionsBase` 特性（DisplayName/Description/VisibleCondition）渲染。

## 4. 服务端 API 客户端（ApiClient.cs）

静态类，进程级单例 `HttpClient`（`SocketsHttpHandler`：连接超时 30s、KeepAlive ping 30s、连接池寿命 10min、空闲 90s）。所有请求带 `Accept: application/json` 与 `User-Agent: MetaTube/{插件版本}`；配置了 Token 时加 `Authorization: Bearer {Token}`。

响应统一信封 `ResponseInfo<T> { data, error { code, message } }`：非 2xx 且带 error 时抛 `API request error: {code} ({message})`；data 为 null 也抛异常。

### 4.1 接口清单

| 方法 | 路径 | 参数 | 用途 |
|---|---|---|---|
| GET | `/v1/movies/search` | `q, provider, fallback` | 影片搜索（provider 空 = 全源并发） |
| GET | `/v1/movies/{provider}/{id}` | `lazy` | 影片详情；lazy=false 强制刷新源站 |
| GET | `/v1/movies/aggregate` | `q, field_priority`(JSON) | 跨源字段级聚合 |
| GET | `/v1/actors/search` | `q, provider, fallback` | 演员搜索 |
| GET | `/v1/actors/{provider}/{id}` | `lazy` | 演员详情 |
| GET | `/v1/images/{primary\|thumb\|backdrop}/{provider}/{id}` | `url, ratio, pos, auto, badge, quality` | 图片代理（服务端裁切/缩放/合成角标） |
| GET | `/v1/translate` | `q, from, to, engine` + 引擎凭据查询参数 | 翻译（from 固定 `auto`，to 固定 `zh-CN`） |
| GET | `/v1/translations/term` | `kind, target_lang, source` | 查术语字典；未命中 200 + `found=false` |
| PUT | `/v1/translations/term` | body：kind/target_lang/source/translated_text/engine | 写术语字典（首写优先），返回实际生效译文 |
| GET | `/v1/actor-aliases` | `name` | 查演员身份；`found/ambiguous/person/matches` |
| PUT | `/v1/actor-aliases` | body：names[]/provider/actor_id/source | 回写候选名池，返回生效身份与艺名 |
| POST | `/v1/actor-aliases/lookup` | body：names[] | 批量查身份（整部影片一次请求） |
| DELETE | `/v1/images/cache` | — | 清空服务端原图缓存（整理任务结束时调） |

翻译引擎凭据走查询参数：百度 `baidu-app-id/baidu-app-key`；OpenAI `openai-api-key/openai-api-url/openai-model`；谷歌免费无凭据。

特殊错误语义：术语字典接口返回 **404** 时抛 `TranslationTermApiUnavailableException`（旧服务端没有该路由），上层据此降级为直接翻译，不当普通 API 错误打断刮削。

图片 URL 由 `ComposeImageApiUrl` 拼装：`ratio` 取配置 `PrimaryImageRatio`（演员/合集头像场景固定 0.5/0.66/1.0），`pos` 为裁切位置（-1 = 服务端默认），`auto=true` 表示服务端自动取图，`badge` 为角标列表（§10.1），`quality` 取配置。

### 4.2 数据模型（Metadata/）

JSON tag 与服务端 Go 结构体一一对应：

- `ProviderInfo { id, provider, homepage }` → `MovieSearchResult`（+actors/cover_url/number/release_date/score/thumb_url/title）→ `MovieInfo`（+big_cover_url/big_thumb_url/director/genres/maker/preview_images/preview_video_hls_url/preview_video_url/label/runtime/series/summary）。
- `ActorSearchResult { images[], name }` → `ActorInfo`（+aliases/birthday/blood_type/cup_size/debut_date/height/hobby/skill/measurements/nationality/summary）。
- `TranslationInfo { from, to, translated_text }`；`TranslationTermInfo { found, translated_text }`。
- 演员身份：`ActorAliasResult { found, ambiguous, person{id,stage_name,provider,actor_id}, matches[] }`；批量 `ActorAliasLookupResult { items[] }`。R27 起只有艺名（stage_name），无译名字段。

## 5. 元数据刮削（Providers/）

### 5.1 番号提取（Helpers/SearchKeyword.cs）

刮削关键词是客户端职责，优先用真实文件路径（`info.Path`），其次条目名：

1. 高置信度正则 `MovieNumberRegex` 抽番号，覆盖三类：`字母-数字`（SSNI-830）、`发行数字前缀`（259LUXU-1795）、`六位日期号`（123456-789）。刻意不覆盖 FC2/carib 等冷门格式，避免误抽。
2. 抽不到时返回清理后的原串，交服务端 `number.Trim` 兜底。清理 = `CrackTailRegex` 截掉 AI 修复/破解尾巴（jasna/ltx/wm/restored/版本号等）+ 循环剥离字幕/无码后缀（内置关键字 ∪ 配置关键字，支持 `-U`、`_UC` 分隔符后缀与 ≥3 字符无分隔符后缀）。

同一正则被 `MovieImageProvider` 的跨源图片回退复用，保证主搜索与图片搜索一套规则。

### 5.2 MovieProvider（影片刮削主链路）

实现 `IRemoteMetadataProvider<Movie, MovieInfo>, IHasOrder`（Order=1）。

**GetSearchResults（识别/搜索阶段）：**

- 无 pid：`SearchKeyword.Normalize` 后，开了字段聚合 → 调 aggregate 并把结果存入进程级 `_aggregationCache`（键=关键词）；否则调 `/v1/movies/search`。
- 有 pid：直接 `GetMovieInfo`，`lazy = pid.Update != true`（pid 第 4 段 Update 标记控制是否强制刷新）。
- 开了源过滤：先剔除不在清单里的源，再按清单顺序稳定排序。
- 每个结果转 `RemoteSearchResult`：名 `[源] 番号 标题`，预览图走 primary 接口（ratio=1.0, auto）。

**GetMetadata（落库阶段）：**

1. 聚合模式优先 `TryRemove` 复用搜索阶段的缓存（省一次 7~11s 的全源搜索）；注意「替换所有元数据」刷新不清 pid，聚合模式即使有 pid 也重新聚合。非聚合模式无 pid 时取搜索结果第一条。
2. 详情走 `MovieInfoCache`（TTL 5min，上限 1000）。
3. `EnableRealActorNames`：仅 DUGA/FANZA/Getchu/MGS 源，用番号去 AVBASE 搜索，对 `番号+标题` 归一化（小写、去空白括号）后算 Levenshtein 相似度，≥0.8 视为同片并替换演员列表。
4. **演员身份解析**（§6）：`ActorIdentityResolver.ResolveAllAsync` 把原始演员名解析成「艺名 + 来源 pid + 头像」，同 pid 多写法只留一位。
5. **翻译**（§7）：任一翻译项勾选才执行；失败只记日志保留原文。
6. Genres/Actors/PreviewImages 去空白去重。
7. 渲染模板生成 `Name`/`Tagline`；`OriginalTitle` 保留原标题；`OfficialRating` 固定 `JP-18+`；`PremiereDate/ProductionYear` 取发行日（年份 ≤1 视为无效）。
8. 写 pid（`SetPid`，含 position）；预告片 URL 存 `TrailerUrl` provider id（`PreviewVideoUrl` 优先，HLS 兜底）。
9. `EnableRatings` 时 `CommunityRating = round(score×2, 1)`。
10. `EnableCollections` 且有系列 → `CollectionName = 系列名`（服务端按它建系列合集）。
11. Studio=片商；Tags=系列/片商/厂牌；导演 Person（可关）；演员 Person 逐个附图与 pid。

**演员头像（SetActorImageUrl）：** 解析器已给身份时直接用；没有身份才按搜索名再搜一次演员（第一条结果 + Gfriends 带图结果兜底）。`actor.SetPid` 无条件写——服务端 `SavePeopleMetadataAsync` 会把 `PersonInfo.ProviderIds` 抄进 Person 条目入库，这是全库唯一持久保存演员 pid 的地方。头像优先演员详情接口第一张（ratio=0.5），Gfriends 图最后覆盖。

### 5.3 ActorProvider（演员刮削）

- 无 pid 按名搜索取第一条；详情 `GetActorInfo`。
- **显示名**（`ActorNameHelper.ResolvePersonDisplay`）：已有名字（手动修改或上次刮削写入）优先保留 → 空名字用服务端别名表艺名（`LookupActorAlias`，歧义不用）→ 再退回演员接口名。刷新不覆盖手动修正。
- Overview 用日文键值拼 HTML：`別名 / 3サイズ / カップサイズ / 身長 / 血液型 / デビュー`，`\n<br>\n` 连接，空项跳过；别名去掉与主名重复项。
- 生日 → PremiereDate/ProductionYear；国籍 → ProductionLocations。

### 5.4 图片 Provider

**MovieImageProvider**（`IRemoteImageProvider`，Movie）：

- 候选源：用番号（pid.Id 或条目名抽）跨源搜索；开源过滤时按配置优先级取全部命中源；否则「存储 pid 优先 + 第一个其它源兜底」；最后总是补上存储 pid。
- 每个候选取详情后产出 Primary/Thumb/Backdrop 三类图，另对每张 `preview_images` 各产三类。Primary 支持 DMM 高清改写（§10.4）与角标。
- 角标按条目当前状态现算（`BadgeSpec.Build`），保证「刷新并替换图片」后角标不丢、无字幕条目不误加。

**ActorImageProvider**（Person）：按 pid 取演员详情，全部相册图作为 Primary 候选（ratio=0.5）。

**CollectionImageProvider**（仅 Jellyfin，BoxSet）：只支持带 MetaTube pid 的合集（pid 指向演员），取该演员相册作封面候选（ratio=0.66）。不受 `EnableActorCollections` 门控（关开关后既有合集仍可换图）。取消异常原样上抛；其它异常记 Warn 返回空（pid 可能指向已下架演员）。

**ExternalUrlProvider / ExternalIds**：影片与演员详情页外链 `{Server}?redirect={pid}`；`TrailerExternalId`（Key=TrailerUrl）把预告片 URL 暴露为外部链接。pid 格式见 §14.1。

## 6. 演员身份解析（Translation/ActorIdentityResolver.cs 等）

R27 口径：演员只存艺名，显示名一律用服务端汉字优选的艺名；插件负责收集候选名池并回写，优选算法在服务端。

### 6.1 名字拆分（ActorNameHelper.Parse）

来源常见写法「A（B）」：B = 搜索更准的艺名（含假名），A = 来源可能已转换好的汉字名。拆分只认末尾一对全角/半角括号且 A 内无嵌套括号；无括号时整串即搜索名。原始串不删改，拆分结果只用于搜索与候选池。

### 6.2 解析流程（ResolveAllAsync，进程级单例）

```
整片未缓存名字 → 批量 POST /v1/actor-aliases/lookup 预取
每个名字：
  进程缓存命中 → 直接复用
  拆出搜索名 B / 表面名 A
  查预取结果（B 优先，A 兜底）
  ├─ 命中且无歧义 → 取表里艺名与 pid；再取演员详情组候选池回写（source=auto）
  └─ 未命中/歧义 → SearchBestAsync 跨源搜索
       排序：来源质量 → 含汉字优先 → 原始顺序
       前 3 个候选做名字校验（NFKC 归一 + 小写 + 去空白后精确相等）
       都校验不上 → 用排序第一并记日志
     取详情 → 组候选池 → PUT /v1/actor-aliases 回写
     成功：用服务端返回的艺名/pid 覆盖；失败：降级用池首个
按 IdentityKey 去重（provider:actorId；无身份时 name:小写名）
```

关键设计：

- **来源质量排序**：`MINNANO > AVBASE > AV-LEAGUE > ThePornDB > Gfriends > Wikipedia`（MINNANO 有汉字/假名/别名，AVBASE 有真实姓名，Gfriends 只有图所以垫底兜底）。
- **候选池固定顺序**：详情 Name → 详情 Aliases → 表面名 A → 命中轮全部搜索结果名；只做非空过滤与去重，汉字评分交给服务端。
- **负命中缓存**：查不到的名字记 15min TTL，避免同一演员在不同影片反复空查；命中即清除。
- **降级**：别名表任何失败（旧服务端 404、网络错误）→ 进程级 `_storeDisabled` 置位，后续只走「搜索 + 详情」，不打断刮削，只记一条日志。
- 解析结果 `ResolvedActor` 带 `ImageSource`/`GfriendsImageSource`，供 MovieProvider 头像阶段复用，避免二次搜索。

### 6.3 手动改名写回

两条入口都调 `PUT /v1/actor-aliases`，`source=person-edit`（服务端标 manual，此后自动升级不碰）：

- 演员页手动改名后跑「同步演员合集」任务：`SyncPeopleNamesAsync` 把 Person 当前名同步回影片演职表，再按 pid（缺 pid 时用旧名/新名查字典反查身份）写回新名。
- 候选池只含新名本身；复合旧名（遗留「译名（艺名）」）查不到 stage_key 时记 Warn，由用户删旧 Person 重刮。

## 7. 翻译子系统（Translation/）

### 7.1 总体编排（TranslationHelper）

- 目标语言固定 `zh-CN`；`IsEnabled` = 4 个翻译项任一勾选。
- 标题/简介：每次刮削直译（主辅引擎链），失败保留原文，单字段失败不影响其它字段。
- 系列/类别：走 `TermTranslationService`（全库统一译法，进程缓存 + 服务端字典）。
- 演员名不翻译（走身份解析）。
- 翻译后的值直接用于派生数据：合集名、标签、Studio、模板变量。

### 7.2 主辅引擎链（TranslationEngineChain）

```
主引擎 OpenAI（OpenAiApiKey 非空才启用）
  成功 → 返回 (译文, "OpenAi")
  失败/未配置 ↓
辅引擎（配置选择）
  Baidu：凭据缺一视为不可用
  GoogleFree：免费接口
  None：不回退
都失败 → 抛异常（术语服务靠异常区分「引擎失败」与「译文=原文」）
调用方取消（OperationCanceledException）直接上抛，不触发回退。
```

返回 `EngineTranslation(Text, Engine)`——Engine 是**实际产出译文的引擎**，术语入库时记录它（主辅回退后可能与配置不同）。

### 7.3 引擎调用（ServerTranslationEngine）

真正请求都发给服务端 `/v1/translate`（插件不直连翻译 API），引擎差异体现在查询参数与限速：

| 引擎 | 请求间隔 | 凭据参数 | 备注 |
|---|---|---|---|
| OpenAi | 1000ms | openai-api-key/url/model | 模型先经 OpenAiHelper 解析 |
| Baidu | 1000ms（1 rps） | baidu-app-id/key | |
| GoogleFree | 100ms | 无 | 长文本按 600 字符分块（日文 URL 编码约膨胀 9 倍，防超长拒绝），切点优先自然边界（换行/`>`/句号等）；每块硬超时 20s |

全局 `SemaphoreSlim(1)` 串行 + 每请求前延迟限速 + 失败重试 5 次（取消不重试）。

### 7.4 术语字典（TermTranslationService + ServerTermStore）

链路：`进程缓存 → 服务端字典 GET → 引擎直译 → PUT 回写 → 以服务端返回的生效值为准`。

- 缓存键 `kind:原文小写`，进程生命周期有效（同一系列/类别只查一次库、只翻一次）。
- 字典不可用（404/网络/数据库错误）→ 进程级降级为直接翻译，不再每术语白等超时。
- 译文含换行 → 保留原文（术语会当合集名/标签，换行会弄坏库里的名字）。
- 引擎失败不缓存，下一部影片可重试；「译文=原文」也入库（避免重复翻译）。
- 并发写同一术语时首写优先，以服务端返回的生效译文为准。
- kind 只有 `series` / `genre`，与服务端 `translation_metadata.kind` 对应。

### 7.5 OpenAI 模型自动发现（OpenAiHelper）

配置了模型直接用；否则依次探测 `{base}/models`、`{base}/v1/models`（10s 超时），取首个「对话模型」——排除 id 含 embedding/whisper/tts/dall-e/moderation/rerank 的项。结果按 baseUrl+apiKey 缓存。`TranslationHelper` 在每次翻译前预解析一次并记日志（主引擎没配密钥时不探测，避免每张影片白等）。

## 8. 演员合集体系（仅 Jellyfin）

设计口径：合集由计划任务与事件监听维护，不在刮削链路里写；关掉开关只停维护，不删已有合集。

### 8.1 组成与分工

| 文件 | 职责 |
|---|---|
| `ActorCollectionSync` | 纯计算：分组、索引、差集计划、封面决策。不引用 Jellyfin 类型，可离线单测 |
| `ActorCollectionUpdater` | 逐组写入：解析 pid → 算差集 → 建/补合集 → 对齐封面 → 写片数。两条入口共用 |
| `SyncActorCollectionsTask` | 每日 4:00 全库「全删重建」 |
| `CollectionWatcher` | 事件驱动的增量同步（单片刷新后即时进合集） |
| `ActorCollectionLock` | 进程级 SemaphoreSlim(1)：全量重建与增量互斥 |
| `ActorCollectionScope` | 媒体库白名单解析与命中判断（空 = 全部库） |
| `CollectionCoverSync` | 合集封面对齐演员 Person 主图 |
| `NoActorCollectionSync` / `MultiActorCollectionSync` | 「无演员影片」「多人共演」两个固定名合集 |
| `EmptyCollectionCleaner` | 删除没有任何存活成员的合集 |

### 8.2 每日全量任务（SyncActorCollectionsTask）

1. 开关关闭直接返回；阈值 <1 按 1 并记 Warn。
2. 查全部带 MetaTube pid 的影片（`HasAnyProviderId` 同时带 `MetaTube`/`metatube` 两种键——历史数据两种写法并存，数据库查询大小写敏感）。白名单非空时：先取全库 id 作移除作用域，再按 `AncestorIds` 取范围内影片作分组来源。
3. 持 `ActorCollectionLock` 全程。
4. **演职名同步**（`SyncPeopleNamesAsync`）：Person 条目当前名 ≠ 演职行名 → 更新演职表（`UpdatePeopleAsync`），并把新名以 `source=person-edit` 写回服务端演员表（§6.3）。这一步让演员页手动改名传导到影片页与合集名。
5. 逐片读演职表（`GetActors`）：无演员 → 无演员合集候选；演员数 >2（去重后）且开多人共演 → 多人共演候选；其余按「影片×演员」展开成 `ActorRef`。
6. **全删重建**：删除插件维护的旧合集（带 MetaTube pid 的演员合集 + 固定名「多人共演」「无演员影片」；用户手建无 pid 合集不动），`DeleteItem(DeleteFileLocation=true)` 连目录一起删。随后以空索引逐组建新合集。
7. 每组：
   - 成员按演职表反查全量（`GetActorMovieIds`，用库里原始演职名精确匹配——演职表名字比较是二进制精确的，Trim/降大小写会一条都查不到），并上白名单；查不到时保留本次扫描结果。
   - `Updater.SyncGroupAsync`（§8.3）。
8. 无演员/多人共演合集对齐（移除作用域 = 有演员影片 ∪ 白名单外影片；手工加入的非 MetaTube 条目永不移除）。
9. `EmptyCollectionCleaner.RemoveAll` 兜底清理。
10. 汇总日志：pid 来源统计（Person 命中 vs 在线搜索）；Person 全库无 pid 时记一条 Warn 提示先刮一遍。

### 8.3 逐组写入（ActorCollectionUpdater.SyncGroupAsync）

**pid 两级解析：**

1. 读 Person 实体（`ReadActorPid`，本地查询零成本）——刮削时写的 pid 由服务端抄进 Person 条目，这是唯一持久位置。
2. 仅当 `ShouldSearchActorPid` 判定「本轮必然要往合集写 pid」时才在线搜索（新建且过阈值 / 已有合集缺 pid）；稳态不搜，避免每日任务对几千演员重复跨源搜索。搜到的 pid 写回 Person 实体（下轮不再搜），并按 pid 重新匹配已有合集（用户改过名的合集只有 pid 认得出）。

**差集计划（ActorCollectionSync.Plan）：**

- 无合集：片数 ≥ 阈值 → Create；否则 Skip（记 SkipReason）。
- 有合集：`add = 期望成员 − 现有成员`；`remove = (现有成员 ∩ 移除作用域) − 期望成员`——只移除本次扫到的 MetaTube 影片，手工条目与范围外条目不动。
- 索引匹配先 pid 后同名：pid 索引 provider 段大小写不敏感、id 段序数敏感（j-9 与 J-9 是不同演员）；同名命中且双方 pid 不同 → `NameConflict` 记 Warn（撞舞台名常态，仍复用不改名）。
- 成员相等且 pid 不缺 → None（幂等，不写库）。
- Update 时**不改合集名**（尊重用户手动改名）；Create 时用演员显示名原样（不加前后缀）。

**写入顺序**：建合集（`CreateCollectionAsync` 带 pid）→ 校验 LinkedChildren 补齐漏成员 → 增/删成员 → 补写 pid（`EnsureCollectionPidAsync`，读-改-写整体回写，必须排在成员之后避免快照覆盖）→ 对齐封面 → 写片数评分。

### 8.4 增量监听（CollectionWatcher）

订阅 `ItemRemoved` / `ItemUpdated`，三个去抖工作器：

| 事件 | 去抖 | 动作 |
|---|---|---|
| Movie 删除 | 5s（批量删除合并） | `EmptyCollectionCleaner.RemoveAll` |
| Person 且 `ImageUpdate` | 3s + 200ms 间隔 | 找到该演员的合集（pid 优先、同名兜底）对齐封面 |
| Movie 且 `MetadataImport/Download/Edit` | 5s（整库刷新攒批） | 按该批影片做增量同步（同一 Updater） |

增量与全量同口径：持同一把锁；只处理带 MetaTube pid 且在白名单内的影片；成员仍按演职表取全量，移除范围只限本批。Person 的普通元数据刷新不触发（整库刷新会成千上万条）；纯图片更新不触发合集同步。合集/演员写入自身再触发的事件不会自循环（影片只认元数据类型、演员只认换图）。

### 8.5 封面同步（CollectionCoverSync）

口径：以演员 Person 条目当前主图为唯一基准，每轮对齐，一致才跳过。

- 源文件优先认 `Person.Path/folder.{jpg,jpeg,png,webp}`（ImageSaver 对 Person 固定落 folder.*；旧版守护曾把指针改到共用 poster.jpg，直接读指针会复制错图），其次才读主图指针。
- **复制而非引用**：Jellyfin 换图会删旧本地文件，合集若指向 Person 头像路径，用户给合集换图会连演员头像一起删。
- 幂等指纹 `.metatube-cover`（合集目录内）四行：来源类型 / 源路径或相册 URL / 源文件修改时间 ticks / 上次写出的封面路径。任一段不符就重写。
- Person 无本地图时回落：仅当合集缺图才下载演员相册第一张（ratio=0.5，与 ActorImageProvider 同取位），避免每天重复下载。
- 为什么不只靠 CollectionImageProvider：它只「供图」，服务端自动抓取时从相册选哪张不可控（相册混着横屏剧照），这正是封面「先对后错」的来源之一。

### 8.6 片数评分（EnableCollectionCountRating）

12.x 没有可排序的「子项数量」字段，借 BoxSet 用不到的 `CommunityRating` 承载存活片数：库页按「公众评分」排序即按片数排。存活成员 = LinkedChildren 去重后批量查库（外键 NoAction，影片删除后链接仍在，不能直接数链接）。值没变不落库；关开关清回 null。

### 8.7 特殊合集与清理

- 「无演员影片」：带 pid 但演职表无演员的影片；「多人共演」：去重演员数 >2。两者无 pid，不参与演员合集匹配；最后一个成员移出后立即删（不等每日任务）。
- `EmptyCollectionCleaner`：不区分是否演员合集，逐个确认成员是否存活（`GetItemById`），全死即删（连目录）。每日任务兜底 + 删除事件即时触发。

## 9. 主图本地化体系

### 9.1 问题背景

插件图片地址是指向服务端的远程 URL，Jellyfin/Emby 只在「下载成功的那一次」有图；角标参数变化或刷新替换图片会重新下载，断网/代理失效时旧图因「地址对不上」被弃用，海报凭空消失。

### 9.2 PrimaryImageStore（落盘）

- 路径：单片目录 `poster.jpg`；多片共用目录（按视频扩展名统计「不同片名」>1，`xxx.com@` 前缀归一，5min 目录缓存）改 `<文件名>-poster.jpg`。Folder 类条目（12.x BoxSet 是真实目录）直接返回 null，防止全部合集共用父目录 poster.jpg。
- 角标指纹：`poster.jpg.metatube` 存生成时的 badge 串，一致即跳过网络请求（断网稳定的关键）。
- 下载校验：HTTP 2xx + `Content-Type: image/*` + 文件头魔数（JPEG/PNG/GIF/WEBP），任何一条不满足返回 `(null, 原因)`，绝不把错误 JSON 写成海报。
- 写入：临时文件 + `File.Move` 原子替换，避免半张图。

### 9.3 PrimaryImageSync（单条目确保）

`EnsureAsync(item, badge)`：本地已有且指纹一致 → 只修指针；否则取影片详情（含 DMM 高清改写）拼图片 URL → 下载 → 落盘 → 指向本地。失败返回原因，调用方保留旧图。

### 9.4 PrimaryImageGuard（守护，IHostedService）

- 监听 `ItemUpdated`（只认 Movie）：主图被改回远程地址且本地海报还在 → 立即指回（5s 冷却防自循环）；本地海报被删（典型「刷新元数据+替换图片」）→ 入队后台补。
- 补图队列：上限 3000，单线程顺序处理，每条等 45s（避开服务端「先删后下」），条间 150ms，按当前角标重新生成。
- 启动 30s 后全库兜底扫描一遍（只读文件系统，断网可完成）。
- 空图（用户手动删）与指向其它本地文件的情况不动——覆盖它们等于撤销用户操作。

### 9.5 整理元数据任务（OrganizeMetadataTask，每日 3:00）

1. 查全部 MetaTube 影片（双 provider 键）。
2. 按文件名/外挂字幕检出中文字幕 → 增删 `中文字幕` genre。
3. `BadgeSpec.Build` 算角标 → `SetPrimaryImage`：指纹一致跳过；能下载就落盘指向本地；下载失败但本地有旧图 → 指回旧图（宁可角标旧，不要空白）。
4. genre 去重 + 自然排序（Emby 用内置 AlphanumComparator），有变化才 `UpdateItemAsync(MetadataEdit)`。
5. 结束调 `DELETE /v1/images/cache` 清服务端原图缓存（海报已落媒体目录）；失败只记 Warn。

## 10. 角标与字幕/无码检出

### 10.1 角标参数（BadgeSpec）

服务端图片接口 `badge` 参数语法：逗号分隔列表，`tr:` 前缀 = 右上角。例：`zimu.png,tr:uncensored.png`（左上中文字幕 + 右上无码破解）。

- `HasChineseSubtitle(item)`：genre 含「中文字幕」或文件名/外挂字幕检出。
- `Build`：`EnableBadges` 且有字幕 → 加 `BadgeUrl`；`EnableUncensoredBadges` 且无码检出 → 加 `tr:UncensoredBadgeUrl`。
- `GetBadge/Matches`：从图片 URL 查询串解析 badge 值（URL 解码），用于比对是否需要重新生成。

### 10.2 中文字幕检出（ChineseSubtitleDetector）

- 内嵌：文件名按 `[-_\s]` 分词匹配关键字（SONE-263-UC），多字符关键字支持直接后缀（cjod288ch），中文关键字按包含匹配。
- 外挂：同目录存在与视频同名的字幕文件，扩展名 ass/srt/ssa/smi/sub/idx/psb/vtt，语言码在配置清单内（正则 `\.(语言)\.(ext)$`，去掉后缀后与视频 basename 精确相等）。
- 网络路径不可达一律视为无字幕，不影响刷新。

### 10.3 无码/破解检出（UncensoredDetector）

内置默认清单始终参与：`U,UC,AI,uncensored,无码,破解,LTX,wm,restored,jasna,cracked,remastered,decensored,leaked,nomosaic`，再并上配置清单。分词分隔符 `[-_\s.@\[\]()（）]`；匹配规则与字幕检出相同（分词 / 长关键字后缀 / 中文包含）。

### 10.4 DMM 高清封面改写（DmmCoverRewrite）

上游 issue 653：JavBus/JAV321/FANZA 的 cover_url 是 `pics.dmm.co.jp` 的 800×538 转存图，同一作品在 `awsimgsrc.dmm.co.jp` 有 2184×1468 版本（Jellyfin 海报位 2:3 裁切后 358×538 vs 978×1468）。

- 正则只认文件名恰好 `<cid>pl.jpg` 的两种 CDN 路径（剧照 jp-*.jpg、缩略图 ps.jpg 不误换），提取 cid 改写为新 CDN；已是新 CDN 原样返回（幂等）；取不到 cid 返回 null 保持原图。
- 纯字符串改写、不落库，由 `MovieImageProvider` 与 `PrimaryImageSync` 在拼图片 URL 时应用；服务端照常取图裁切。

来源：设计 L65–66、L69（探针 `~/metatube-probe/api-probe` 反射 Jellyfin.Controller 10.11.0）：
