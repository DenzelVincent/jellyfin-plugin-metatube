# 演员别名表与名字解析设计

- 日期：2026-11-11
- 状态：已实施（服务端 `a49f634`，插件 `f38f1b6`；待发布与实机）
- 涉及仓库：`jellyfin-plugin-metatube`（插件）、`metatube-sdk-go`（服务端）

## 1. 背景

影片来源返回的演员名会出现 `柚井初美（ゆい はつみ）` 这种「汉字名（括号内写法）」：

- 括号内是搜索更准确的艺名/假名/罗马字，页面只应显示括号外的汉字名；
- 同一演员还可能有多个艺名、假名读音、英文拼音，换厂商或改名后名字也会变，但仍是同一个人；
- 直接删掉括号内容会丢信息；直接把整串入库又会让同一演员在不同来源下裂成多个 Person。

因此名字**原样保留**，用一个演员身份 + 别名关系表把各种写法归到同一个人；显示、搜索、翻译、
Jellyfin 的 Person 匹配都按身份走。

## 2. 名字模型

服务端只维护一张 `actor_person`，一人一行：

- `stage_name`：搜索用的艺名（影片接口里的 B；`A（B）` 时取括号内，没有括号就是整串）。
- `translated_name`：显示/合集名用的译名（影片里的 A，或引擎翻译 B 的结果）。

`A` 是数据源已经转好的汉字名，存在时直接作为译名写入（不调用引擎）；不存在时才翻 `B`。
演员其他信息（生日、三围、图片、aliases）只用于资料展示，不再入表。

展示规则：

- 「翻译演员名」开启时显示译名；关闭时显示艺名 B。
- 搜索一律先用 B；同一部片按 pid 去重。
- 真实姓名（AVBASE）等来源只影响 B/资料，不产生第三个显示名。

## 3. 服务端

### 3.1 表

- `actor_person`：`id`、`stage_name`（复用旧 `display_name` 列）、`stage_key`、
  `translated_name`、`translated_key`、`translation_source`、`provider` + `actor_id`（唯一）。
- 匹配键：NFKC 全半角统一、去首尾空白、忽略大小写与所有空白；不做截断。
- 艺名稳定不覆盖；译名为空时补写；数据源给的译名（A）可覆盖引擎译文。
- v1.8.5 的 `actor_name` 明细表已废弃，启动时删除；旧 `actor_person` 行自动补键。
- 与术语字典同库，部署仍需文件 SQLite（`-dsn`）。

### 3.2 接口（私有路由）

- `GET /v1/actor-aliases?name=`：按艺名或译名查身份；同名多身份返回 `ambiguous` 与 `matches`。
- `PUT /v1/actor-aliases`：`{stage_name, translated_name, translation_source, provider, actor_id, source}`；
  按 `provider + actor_id` 找到或创建身份，幂等。
- `POST /v1/actor-aliases/merge`：`{person_ids, stage_name, translated_name}`，手工合并。

### 3.3 MINNANO 名字增强

现有 `provider/minnano` 解析「名字（假名 / 罗马字）」行；参考 `kanojo-db/scrapers`
的 `minnanoav.py`，再补 h1 日文名与 h1/span 英文名兜底（两个词时交换姓/名）。

## 4. 插件

### 4.1 名字拆分

`ActorNameHelper.Parse` 只拆分不修改：`A（B）` → 显示 `A`、搜索 `B`；无括号或括号为空时两者相同。
`Classify` 按字符组成给出 `kana` / `romaji` / `stage` / `alias`。

### 4.2 身份解析

`ActorIdentityResolver.ResolveAllAsync`：

1. 按原始名解析显示名/搜索名；
2. 依次用「搜索名 → 显示名 → 原始名」查别名表；
3. 命中唯一身份 → 直接用其规范名、pid 与译名；
4. 未命中（或歧义）→ 演员搜索（搜索名优先）+ 演员详情，取规范名与 aliases；
5. 把原始名、显示名、搜索名、详情名、aliases 按角色回写，未开启翻译时也回写；
6. 同一部片按 pid 去重；不同演员译成同名时后者回退原名；
7. 进程内按原始名缓存，避免同一演员重复查表/搜索。

演员翻译仍走服务端术语字典（键为规范名），同一身份的不同写法共享译文。

**合集名**：新建演员合集时按影片里的演员显示名查别名表：开启「翻译演员名」取 `translation`，
否则取表里的规范显示名；旧服务端或查询失败时退回影片里的显示名。已有合集仍不自动改名（R18）。

**多来源选择**：搜索结果按演员数据质量排序，而不是服务端优先级：
`MINNANO → AVBASE → AV-LEAGUE / ThePornDB → Gfriends → Wikipedia`，同来源内优先带汉字的名字。
然后逐个取详情，用 `name/aliases` 与查询名做归一化匹配；最多尝试 3 个候选，
全部校验不上时退回排序第一的候选并记日志。Gfriends 只有图片，只作最后兜底，
它的头像也不需要靠选它来拿——服务端返回日文来源详情时本来就会注入 Gfriends 图片。

### 4.3 头像

`PersonInfo` 显示最终名字；pid 与头像用解析出的演员身份。头像优先取
`/v1/actors/{provider}/{id}` 的 `images` 第一张；仅在没有 pid、需要搜索时保留
Gfriends 覆盖。

### 4.4 降级

- 旧服务端没有 `/v1/actor-aliases`（404）或网络/DB 错误：进程内禁用别名表，只 Warn 一次，
  退化为「演员搜索 + 详情」，刮削不中断。
- 搜索不到演员：保留解析出的显示名，不猜身份、不回写。

## 5. 边界

- 别名只增不删；自动流程不做跨身份合并，同名不同人只能手工合并。
- 已有 Jellyfin Person 不会自动改名，需要重刮；旧名字对应的 Person 会由日常清理回收。
- 服务端必须使用文件 SQLite 才能跨重启保留别名表；内存库重启即丢（可重新学习）。
- 术语字典与别名表都按来源 pid 记录，不区分 provider 的同名演员会以歧义形式暴露，不自动选。
